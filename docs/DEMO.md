# The synthetic 50-case demonstration

**DEMO / SYNTHETIC FIXTURES — NOT A REAL MODEL BENCHMARK.** This opt-in walkthrough proves that registration, workers, tool arguments, evaluators, traces, failures, regression, replay, cost gaps and reporting are connected to **executed records**. It does not claim a language model can analyze revenue data, nor that a prompt revision caused a real model regression.

## What is seeded and what is measured

`POST /demo/seed` (or `AGENTLAB_DEMO_SEED=true` on startup) registers **only**:

- Agent `DEMO · Dataset Research Agent`: deterministic `mock` provider; v1 calls `dataset.aggregate` with a `region` and `month`, v2 has an explicit controlled fault policy that omits `month` on every fifth fixture case.
- Benchmark `DEMO · Revenue Analysis / 50 cases`: 5 synthetic regions × 10 months, each with a versioned input, reference output, JSON schema and explicit tool-argument rule. Dataset rows are generated by the deterministic formula in `packages/agentlab/demo_fixtures.py`. No external dataset or real model is involved.

**No run/evaluation/metric is inserted by seeding.** `POST /demo/run` creates **new** pinned baseline and candidate experiments, each queues 50 actual mock tasks, then workers execute the tool/evaluator pipeline. The UI displays pending progress until final metrics exist. The fixture's month omission is a deliberately reproducible tool-argument failure. If the worker/broker is down, metrics remain unmeasured/queued rather than showing canned numbers.

In the automated integration/E2E executions of this fixture (2026-09-27), measured **DEMO** baseline v1 passed **50/50** completed cases (task success **100%**); candidate v2 passed **40/50** (task success **80%**) and had **10 tool-argument failures**. A paired comparator on those executed run IDs marked `REGRESSION` with **10 previously passing paired runs now failing**. These are **fixture measurements only**. Any agent using the `mock` adapter is labeled **DEMO**, even if registered by an operator rather than preseeded. The mock reports **no tokens and no model price**, so candidate inferred cost is **Not measured**; no latency/cost number is prewritten into the demo. Rerunning the demo produces new IDs and measurement timestamps, preserving previous results.

## UI walkthrough

1. Visit **Overview** or **Experiments** → **Run 50-case demo**. Both jobs move QUEUED → RUNNING → COMPLETED. Check DEMO badge, version IDs and metric provenance; after evaluation there are 100 executed run records across the pair.
2. Select **Compare versions** and submit. Review paired new failures, verdict, thresholds and null cost deltas. Click **Inspect failure** to see expected vs observed, classification evidence and exact tool args in **Open complete trace**.
3. Click **Replay failure**. This creates a *new* experiment pinned to the original task/version/seed/run index. If its status and output hash exactly match the deterministic mock, the replay is marked **REPRODUCIBLE**. Do not extrapolate this verdict to an external provider.
4. Go to **Robustness**, select the DEMO benchmark, choose transformations and a seed, generate a **new** suite. Run that suite against a pinned agent version; only meaning-preserving variants count toward `robustness_rate`. Optionally set **Runs per task** to 2–20 for per-task Wilson intervals and observed variance. Tool faults remain simulated/sandboxed.
5. Visit **Cost & latency** for measured tool/run wall-clock values and **Not measured** token/cost coverage. In the completed experiment, click **Generate report**; export an immutable Markdown/JSON/standalone HTML snapshot or a PDF rendered from the frozen JSON. PDF generation does not re-evaluate the agent.

## Reproduce through API

```bash
agentlab demo seed
agentlab demo run --seed 42                   # copy returned baseline/candidate IDs
agentlab experiment status BASELINE_ID        # poll until status COMPLETED
agentlab experiment status CANDIDATE_ID
agentlab regression compare BASELINE_ID CANDIDATE_ID
agentlab failure list --experiment CANDIDATE_ID
agentlab failure replay FAILURE_ID
agentlab report generate CANDIDATE_ID --format pdf --out demo-evidence.pdf
```

For programmatic scripts, use `GET /experiments/{id}` and wait for `completed_at` before comparing/generating a report. Tests assert exact fixture outcomes; timing and output IDs are naturally measurement-dependent. Do not publish these fixture values as a model leaderboard.
